# 空间关系解释：开源调研与设计

Disk Sense 的核心不是复刻磁盘占用图或增加清理规则，而是把孤立路径还原成软件、项目和系统组件的空间关系。

## 可借鉴的开源机制

- [Bulk Crap Uninstaller](https://github.com/BCUninstaller/Bulk-Crap-Uninstaller) 会聚合 Windows 应用信息、识别孤立应用并寻找卸载残留。Disk Sense 借鉴“一个应用拥有多个系统足迹”的概念，但不复用其卸载逻辑。
- [Syft catalogers](https://oss.anchore.com/docs/guides/sbom/catalogers/) 使用多个独立 cataloger，根据清单、目录结构和二进制特征识别软件包。Disk Sense 借鉴“多识别器 + 证据输出”，用于识别项目和数据角色。
- [BleachBit CleanerML](https://docs.bleachbit.org/cml/cleanerml/) 用声明式规则描述应用路径、匹配方式和操作。Disk Sense 借鉴声明式角色规则，但规则首先用于解释，不能直接赋予删除权限。
- [osquery](https://github.com/osquery/osquery) 将 Windows 程序、服务、计划任务、启动项和路径暴露为可关联事实。后续可以把这些系统事实作为应用归属证据，而不是只依赖目录名称。

这些项目都只覆盖问题的一部分；没有发现一个开源项目能直接完成 Disk Sense 所需的跨位置空间解释。因此实现采用原创的数据模型和安全边界，不复制第三方代码。

## Disk Sense 关系模型

一个解释结果由五部分组成：

1. `entity`：软件、项目、系统组件或仍未确定的实体。
2. `root`：能够代表该实体的安装根、项目根或数据根。
3. `role`：程序本体、源代码、依赖、构建产物、缓存、日志、配置、用户数据或临时数据。
4. `edges`：当前对象与根目录、跨盘位置及其他数据目录之间的关系。
5. `evidence`：清单文件、目录结构、标准 Windows 路径、文件签名和已知应用特征；每条结论必须能回溯到证据。

## 当前实现

- 从选中对象向上进行有界查找，识别 Node.js、Python、.NET、Java/Gradle、Rust、Go、PHP、Unity、Unreal 和通用 Git 项目。
- 使用主标记与辅助结构共同计算置信度，不因单个 `src`、`cache` 或相似名称直接认定归属。
- 识别对象在所属实体中的角色，包括源代码、依赖、构建产物、缓存、日志、配置、用户数据、临时数据和运行组件。
- 对 AppData、ProgramData、Program Files 等标准路径进行保守的应用足迹推断；没有已知签名时降低置信度并明确标记为推断。
- 读取 Windows 卸载注册信息，以显示名称、发布者、安装目录和程序图标目录验证应用归属；查询结果有时限缓存，失败时自动退回原有本地判断。
- 解析用户选中的 Windows 快捷方式，将快捷方式本身、真实目标和目标所属应用串成可追溯关系。
- 将关系根、角色和证据显示在解释面板，并作为结构化证据提供给可选 AI 分析。

## 后续证据源

后续可继续增加正在运行的进程、服务、计划任务、文件签名发布者和时间相关性。这些都应作为新的 cataloger 接入，不得绕过本地风险规则，也不得把“相关”直接等同于“可删除”。进程是否运行只说明当前使用状态，不能单独证明归属或决定是否可清理。
