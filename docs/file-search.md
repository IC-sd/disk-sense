## 索引和启动

- 启动后立即使用已有 SQLite 索引。启动不再因为索引超过两小时，就在 45 秒后开始全盘重建；正常同步由文件监听和定期校对完成。
- 新磁盘、首次建立索引或中断的扫描仍会在后台处理。已有记录始终可以搜索，首次扫描期间每次提交的新记录也会刷新当前查询。
- Windows 使用 `search-enumerator.cs` 调用 `FindFirstFileExW/FindNextFileW`，一次枚举取得名称、属性、大小和修改时间，省去逐文件 `lstat`。无须管理员权限。辅助程序在应用缓存目录编译，不能使用时回退到 Node 扫描。
- 扫描先收录常用目录与开始菜单，再处理系统目录、依赖包和缓存。低优先级目录仍会被收录。目录链接和重解析点不进入递归。
- 待扫描目录和已经完成的目录存放在 SQLite 中，进度检查点保留 generation。应用退出后可继续未完成的目录；整轮成功后再清除过期记录，无权限的子树保留原记录。
- 状态中的可搜索数量来自已提交的记录。后台扫描不再把整个搜索页面标记成尚未可用。

### NTFS 加速（2026-10-18）

固定 NTFS 卷增加 MFT 文件记录快照和 USN 日志回放。搜索页的“启用开机加速”通过首次 Windows 管理员确认，安装到受保护的 Program Files 目录，以 Windows 服务自动启动；主界面保持普通权限。应用或服务重启后自动连接，并从 SQLite 保存的日志游标补收变化，不需要每次重新授权。服务二进制更新、安装或卸载需要管理员确认。“关闭开机加速”保留索引。首次收录和日志断档时才建立快照，多盘中断后仅重建未完成的卷。

已覆盖新增、修改、删除、硬链接、父子目录同时改名、交换目录名称、大小写改名和子树移出被删除目录。NTFS 卷使用 USN 同步，普通文件系统继续使用目录监听和校对。中断快照不会清空原索引，辅助进程支持取消后重连。协议、权限及逆向依据见 [NTFS 索引研究](ntfs-search-research.md)。

批量索引采用短事务，避开逐条 `RETURNING` 的临时结果开销。快照用代次识别过期条目，USN 中未变化的文件不重写代次或目录关系；大小/时间变化只更新元数据列。删除按路径范围定位，避免每次遍历整卷关系表。全量写入期间将 WAL 自动检查点提高至 16,384 页，结束后恢复；USN 文件更新按 256 个变更提交，完整应用后才推进游标。服务短暂中断保留游标并自动重连。

Win32 枚举返回的属性适合搜索展示，后续文件操作仍须重新检查文件。API 说明：[Microsoft FindFirstFileExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirstfileexw)。

## 查询和结果

- 文件名和目录路径独立召回，再统一应用目录范围、类型、扩展名和滚动时间窗口。存在名称命中时，路径命中仍会保留。
- 目录搜索先筛选目录，再通过有索引的路径区间取后代文件；显式固定目录在先的连接顺序，避免 SQLite 反过来遍历百万文件再逐项检查目录。
- 支持多词 AND、引号、`ext:pdf`、`folder:`、`file:`、通配符、两种路径分隔符和分段路径。尚未输入完整的 `ext:` 不会触发全盘全部结果的物化。
- 精确名称、前缀、名称包含和路径匹配在截取页面之前排序。模糊应用入口独立补充，普通文件的词首与驼峰缩写也独立召回。
- 模糊匹配通过动态规划选择连续字符和词首边界，支持驼峰缩写。应用标题高亮偏向词首，例如 `n` 对 `OneNote` 选择后面的 `N`。文件 Keyword 高亮保留首个字面位置。
- 支持拼音全拼、首字母、部分拼音和多音字候选。已有索引的中文别名分批补齐，不要求重新遍历磁盘。排名和标题高亮共用匹配位置，并将拼音库的 UTF-16 位置转换为界面使用的字符位置。
- 查询返回 session、命中数量和下一页位置。页面每批加载 100 项，滚动或点击“加载更多”继续读取。会话固定排序和文件身份，索引更新不会重新排列已经开始翻页的列表。相关度排序合并重复应用入口，显式名称/日期排序保留物理文件。
- 同一数据库指纹下短时间重复查询复用会话；连续不同输入完整重召回 ID，复用已有候选的排名数据，只为新 ID 读取排名列。外部提交、同连接写入及版本竞争会使不安全的复用失效。缓存默认最多 4 个会话、64 MiB 保留字节估算；单个超预算的活跃会话仍保留，以维持完整翻页。连续输入通过共享取消版本中断过时请求，界面同时检查请求序号，防止旧结果覆盖新输入。
- 普通文件的词首、驼峰缩写独立召回，不再以已有结果不足 30 条作为条件。ASCII 缩写通过字符对倒排索引筛选，再校验连续词段与词首跳转；应用保留较宽的 Fuzzy 召回。筛选条件统一作用于各来源。此规则不等同于完整复现 Listary 的通用 Fuzzy 评分。
- 候选会话固定文件身份及排名列，名称、时间、大小和相关度视图独立；改排序复用候选。视图对分区排序，按页面需要逐步归并；第一页和后续页均按需读取完整文件记录。名称/时间/大小排序跳过相关度评分。目录名称召回复用 trigram 索引，原始 basename 在候选会话内共享，保留 camel 边界。
- 成功打开搜索结果后，记录该关键词下的选择，最近的选择优先；旧选择次数不会压过更新选择。相关度排序参考当前浏览目录。明确指定名称、日期或大小排序时不使用选择记忆。记录仅本地保存，排名使用近 90 天数据，最多保留 10,000 条；复制、定位和打开失败不计入。
- 首次升级在后台补齐缩写辅助索引，不重新遍历磁盘；中断后从已保存位置继续。文件新增、改名、删除同步维护辅助索引。同一个文件连续匹配不同查询时，界面也会刷新高亮位置。

## 能力边界

NTFS 已有 MFT 快照和 USN 回放，首次完整 SQLite 建库仍有明显成本。原生读取阶段与完整入库、GUI 延迟分别计量，最新集成记录见 [ntfs-validation.json](ntfs-validation.json)。命中很多的宽泛查询仍有排序成本，不能据此宣称与 Listary 的所有延迟等价。

开机服务消除了临时辅助进程退出后重复授权的限制。首次安装和服务程序升级仍需 UAC。正常开机自动启动已通过服务配置与停止/启动实验验证，未进行实际系统重启。非 NTFS 或未授权时仍通过常规目录扫描收录，应用退出期间的变化依赖后续校对。USN 覆盖、卷更换或超过保护上限的大量积压仍可能要求完整快照。

中文候选转写有预算，多音字不会枚举任意长度名称的全部读音组合；也不承诺复现原软件的所有区域大小写和 Unicode 行为。
